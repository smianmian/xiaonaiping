# BACKEND_DECISION.md

## 文档状态

- 项目：小奶瓶 / 宝宝成长记录
- 阶段：AppLaunchOS v2 后端决策与实现更新
- 日期：2026-06-18
- 当前结论：第一版后端已有本地最小实现、MySQL 适配和聚合运维看板；中国大陆首发还需要华为云 + 宝塔 MySQL 生产部署、真实 OBS、登录服务和远程验证

## 已确认事实

1. 第一版只做 iOS 原生 App。
2. 第一版先做单人记录。
3. 第一版免费验证，先不商业化。
4. 数据本地优先。
5. 第一版需要账号。
6. 第一版需要备份恢复。
7. 服务器需要存储宝宝照片原图。
8. 首发地区改为中国大陆，香港第二批。
9. 数据包含儿童、照片、成长记录、疫苗提醒等高敏感家庭数据。
10. 如果后端进入实现，公开仓库只保留架构原则；具体部署参数放在私有运维文档。
11. 如果与其他服务同机部署，小奶瓶必须完全隔离。
12. 疫苗提醒模板覆盖国内 + 香港，崩溃上报进入第一版。
13. API 服务和对象存储区域必须在发布前按隐私和区域合规确认。
14. 崩溃上报使用 Apple 原生渠道。

## 合理推断

1. 后端的第一版目的应严格限定为账号下的备份/恢复。
2. 项目需要高于纯本地 Level 0，但不需要可查看用户内容的完整运营后台。
3. 最合适的描述是 Level 2.5：账号 + 云端备份恢复 + 对象存储 + 隐私安全的最小运维看板。
4. 照片原图上传会显著增加隐私、成本、对象存储、删除验证和 App Store 隐私披露压力。
5. 当前账号实现采用恢复密钥，不采集邮箱手机号；正式上架前如改用 Apple Developer 账号能力，需要重新审查 Sign in with Apple 和 token 撤销。
6. 同机部署必须使用独立目录、端口、进程和反向代理站点，不能影响任何已有服务。

5. 用户运营后台。
6. 第三方分析平台。

## 基础设施等级判断

| Level | 名称 | 小奶瓶当前判断 |
|---|---|---|
| Level 0 | 纯本地客户端 | 不满足已确认的备份恢复和原图云备份 |
| Level 1 | 本地优先 + 匿名指标 | 不满足账号和备份恢复 |
| Level 2 | 账号 + 订阅 + 远程配置 | 账号需要，但订阅和远程配置不需要 |
| Level 3 | 云同步 + 管理后台 + BI | 需要云端备份，但不需要管理后台和 BI |
| Level 4 | SaaS / 多租户 / 企业权限 | 不适用 |

当前选择：**Level 2.5：本地优先 + 账号 + 备份恢复 + 照片原图对象存储**。

## 决策表

| 问题 | 当前答案 | 结论 |
|---|---|---|
| V1 需要登录吗 | 是 | 需要账号方案 |
| V1 需要订阅权益吗 | 否 | 不做订阅和 IAP |
| V1 需要云同步/备份吗 | 是 | 只做备份恢复，不做多人实时协作 |
| V1 需要管理后台吗 | 只需运维看板 | 只展示聚合健康指标，不查看宝宝内容 |
| V1 需要远程配置吗 | 否 | 不做 |
| V1 需要分析吗 | 待确认 | 只能做隐私安全指标，不采集内容 |
| V1 需要照片原图云存储吗 | 是 | 需要对象存储和删除机制 |
| V1 需要崩溃上报吗 | 是 | 必须脱敏，不上传宝宝内容 |
| V1 疫苗模板范围 | 国内 + 香港 | 不提供医疗建议 |
| 最低可行等级 | Level 2.5 | 账号 + 备份恢复 + 文件存储 |
| 为什么不更低 | 已确认需要账号、备份恢复、原图云备份 | Level 0/1 不满足 |
| 为什么不更高 | 第一版单人、免费、无协作/订阅/内容运营后台 | 不应过度建设 |

## 同机隔离决策

如果与其他服务同机，必须保持已有服务不受影响：

- 不复用或覆盖已有服务目录。
- 不复用已有服务端口。
- 不执行会影响其他服务的全量重启、全量清理或全量迁移命令。

小奶瓶部署参数必须在私有运维文档中单独确认：

- 独立部署目录。
- 独立内部端口。
- 独立进程名。
- 独立反向代理站点和 API 域名。

## 当前结论

后端已从“是否需要”变为“已有本地最小可运行实现、MySQL 适配、聚合运维看板、华为云 ECS 独立部署和宝塔 MySQL 独立库”。当前公网使用 `https://api.mewpow.com/xiaonaiping` 过渡路径并已通过远程验证。下一步是补齐中国大陆生产化剩余项：小奶瓶专属 API 子域名、私有 OBS、手机号/微信真实登录、看板内网访问、备份策略、日志脱敏、删除 SLA 和备案/合规证据。
