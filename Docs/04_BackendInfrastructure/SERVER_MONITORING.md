## 已确认事实

1. 第一版需要账号、备份恢复和照片原图云备份。
2. 如果后端存在，必须有基础监控和日志。
3. 日志不得泄露宝宝敏感数据。
4. 崩溃上报使用 Apple 原生渠道。

## 合理推断

1. 监控应看服务健康，不看用户内容。
2. 崩溃或错误日志需要脱敏。
3. 照片上传/删除失败率需要监控，但不能记录照片内容或对象 key 明文。

## 待我确认的问题

1. 日志保留周期。
2. 告警渠道。
3. Apple 原生崩溃上报脱敏验证方式。

## 不进入第一版的功能

1. 用户增长 BI。
2. 用户内容查看后台。
3. 复杂 APM。

## 已实现的聚合指标

1. 总账号数、活跃账号数、已删除账号数、24 小时新增和 7 天新增。
2. 有云备份的账号数。
3. 云备份总字节数和最近备份时间。
4. 照片对象数量、总字节数和最近照片更新时间。
5. 手机号 / 微信账号标识数量。
6. 待验证短信码数量。
7. 删除审计：删除账号数、删除照片对象数和最近删除时间。
8. 数据库后端和对象存储后端类型。

入口为 `/internal/dashboard`，聚合 API 为 `/internal/metrics`。API 必须使用 `XNP_ADMIN_TOKEN`，生产环境还需通过 Nginx、VPN 或等效内网访问控制限制入口。

生产公网路径 `/xiaonaiping/internal*` 必须保持封禁。需要从本机打开后台时，用 SSH 隧道访问：

```bash
ssh -fN -o ExitOnForwardFailure=yes -L 18787:127.0.0.1:8787 root@YOUR_SERVER
open http://127.0.0.1:18787/internal/dashboard
```

不要把 `XNP_ADMIN_TOKEN` 放进 iOS App、Git、聊天记录或公网页面。

## 已实现的日志脱敏

1. HTTP 访问日志保留客户端、方法、脱敏路径和状态码。
2. `/v1/photos/{photoId}` 会记录为 `/v1/photos/<redacted>`，避免照片对象 key 进入日志。
3. 当前诊断与日志脱敏证明为 `Backend/proof/diagnostics-redaction.json`。

## 生产部署待补

1. API 可用性和延迟。
2. CPU / 内存 / 磁盘。
3. 宝塔 MySQL 连接、容量、慢查询和备份状态。
4. OBS 上传/下载/删除失败率。
5. 备份恢复成功率。
6. 5xx 数量和告警渠道。

## 日志禁止字段

1. 宝宝昵称。
2. 出生日期。
3. 照片 URL 或对象 key 明文。
4. 喂养、睡眠、排便、身高体重明细。
5. 疫苗备注。
