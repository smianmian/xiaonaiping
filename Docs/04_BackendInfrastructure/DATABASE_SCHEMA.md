- 阶段：数据库设计与最小实现更新
- 日期：2026-06-19
- 当前结论：本地默认使用 SQLite；已实现 MySQL 连接、MySQL schema、迁移脚本和第一方合规埋点表；生产目标为华为云 ECS 上宝塔管理的独立 MySQL

## 已确认事实

1. 本地数据库是第一来源。
2. 第一版需要账号。
3. 第一版需要同步恢复。
4. 服务器需要存照片原图。
5. 数据包含儿童和家庭敏感信息。

## 合理推断

1. 服务端数据库应保存最小同步字段和照片对象元数据。
2. 照片二进制不应进入关系数据库，应进入对象存储。
3. 月报可由客户端生成，不必保存冗余内容。
4. 删除字段和保留周期必须设计在 schema 里。
5. 运营分析只能保存行为枚举和聚合所需字段，不保存宝宝内容。

## 生产数据库

1. 使用 `XNP_DATABASE_BACKEND=mysql` 切换到 MySQL。
2. 使用 `Backend/scripts/migrate_database.py` 创建生产 schema。
3. MySQL 配置只从私有环境变量读取，不进入仓库或客户端。
4. 真实宝塔 MySQL 上线前必须完成连接、同步、恢复、故障切换和删除验证。
5. 生产库名和账号必须使用小奶瓶命名空间，例如 `xiaonaiping_prod` 与 `xiaonaiping_app`，禁止复用情绪 App / 一根呆毛数据库。

## 为什么先不拆业务明细表

第一版同步目标是同步恢复和私密家庭协作，不是云端运营查询。账号级 JSON 用于个人灾备；家庭组只把允许类型的档案与记录拆成最小记录信封，按游标增量同步和按更新时间合并，不包含照片原图、照片元数据或提醒偏好。服务端不提供内容查询后台。

## 数据库安全要求

1. 所有表必须按 userId 隔离。
2. 高敏感字段不得写入非必要索引。
3. 同步文件必须有访问控制。
4. 日志和错误上报不得包含敏感字段。
5. 照片对象 key 不得包含宝宝姓名、生日或原始文件名。
6. `analytics_events.account_hash` 必须使用 HMAC，不得保存原始账号 ID。
7. `analytics_events.properties_json` 只能保存白名单枚举，不得保存自由文本、数值明细、照片 key、手机号或微信标识。
8. 账号删除时必须删除对应 `analytics_events` 行。
9. 家庭成员退出/移除、邀请码失效和账号删除必须同步撤销该账号对家庭记录的读写权限；服务端表与迁移必须覆盖该删除策略。
