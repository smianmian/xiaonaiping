# Decisions

## 2026-08-11

### 覆盖决策

- 第一版全球同步首发，不采用按国家或地区分批上线。
- 所有目标地区的强制商店、隐私、儿童数据、备案和基础设施要求属于同一轮发布门禁；任一未满足时阻断整轮发布。

## 2026-07-27

### 覆盖决策

- 第一版正式纳入多宝宝档案和最多 6 名成员的私密家庭协作。
- 家庭组只共享宝宝档案和非照片记录；照片原图、照片元数据、提醒偏好和账号凭证不在成员间共享。
- 家庭协作是异步增量同步，不是公开分享、社交功能或实时共同编辑。
- 成员退出、创建者移除成员、邀请码失效和账号删除后的访问撤销属于 V1 发布前阻断项。

## 2026-06-18

### 覆盖决策

- 公司主体：深圳市闪现生活科技有限公司。
- 全球首发前必须完成中国大陆适用的 APP 备案、ICP / 联网服务判断以及其他目标地区的强制合规信息。
- 当前只有本地最小后端和 SQLite 数据库，不得表述为已经部署到华为云。
- 第一版增加不含宝宝内容的私有运维看板；不建设可查看宝宝记录或照片的运营后台。
- 本节的地区顺序决策已由 2026-08-11 全球同步首发决策覆盖。

## 2026-05-28

### 已确认事实

- 第一版只做 iOS 原生 App。
- macOS、Android、Web 不进入第一版。
- 目标用户以妈妈为主，覆盖宝宝 0-3 岁。
- 第一版免费验证，不做商业化。
- 记录数据本地优先，同时需要评估第一方后端服务器存储。
- 照片可复制进 App 私有空间。
- 首发范围由最新覆盖决策统一管理。
- 第一版需要账号。
- 第一版需要同步恢复。
- 服务器需要存储宝宝照片原图。
- 新框架默认后端部署基线为公开仓库部署原则，但不代表第一版必须做后端。
- 疫苗提醒模板范围：国内 + 香港。
- 崩溃上报进入第一版，使用 Apple 原生渠道。
- 账号策略：开发期先用当前可用账号/开发者资源推进；正式上架前必须准备付费 Apple Developer 账号并完成对应能力。
- 同机部署必须与同机已有服务完全隔离，不能复用已有服务资源或执行全量影响命令。
- API 服务和对象存储区域必须在发布前按隐私和区域合规确认；这里的“区域”就是服务器和照片仓库所在的数据中心位置。

### 合理推断

- 服务器存储应保持最小化，服务账号下的同步/恢复，而不是社交或分析。
- 第一版视觉应温柔、干净、有纪念册感。
- 全球首发前需要同步处理各目标地区适用的备案、儿童/个人信息保护和 SDK 披露。
- 服务器存照片原图会显著提高隐私、安全、存储成本、删除验证和 App Store 隐私披露要求。
- 崩溃上报应优先不携带宝宝内容、照片对象 key、记录明细或账号可识别信息。

### 待我确认的问题

- 是否需要除 Apple 原生崩溃上报以外的线上埋点。
- 云端数据保留周期和删除 SLA。
- 小奶瓶 API 正式域名。
- 付费 Apple Developer 账号开通时间。
- Apple 原生崩溃上报的脱敏验证方式。

### 不进入第一版的功能

- macOS、Android、Web、家庭协作、社区、电商、广告、医疗诊断。
- IAP、订阅、付费墙。
- 管理后台、BI、复杂运营系统。
- 分地区首发。
