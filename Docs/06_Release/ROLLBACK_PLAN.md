## 回滚目标

在发现账号、备份恢复、照片云存储、账号删除或隐私披露不一致时，快速停止风险扩大，并保留删除和恢复证据。

## 可回滚对象

1. iOS App 版本：停止当前 TestFlight / App Store 发布，回退到上一稳定构建。
2. API 服务：切回上一部署目录或上一进程版本。
3. 对象存储：暂停新照片上传，保留已上传对象的删除能力。
4. App Store 元数据：撤回或修正隐私标签、Review Notes、隐私政策 URL。

## 不能回滚的边界

1. 已经发给用户的恢复密钥不能重新展示。
2. 用户已删除的云端账号和照片不应恢复，除非隐私政策明确存在恢复窗口且用户同意。
3. 不得为排查问题导出宝宝照片、生日、备注或记录明细到非生产安全环境。

## API 回滚流程

1. 停止新发布进程。
2. 保持当前数据库和对象存储只读备份。
3. 切回上一版本 API 目录和 systemd 服务。
4. 运行 `Backend/scripts/verify_remote_api.py` 验证健康检查、备份恢复、照片上传/删除和账号删除。
5. 记录回滚时间、版本、原因和验证结果。

## App 回滚流程

1. TestFlight：停止分发问题构建，通知测试用户。
2. App Store：如已提交审核，撤回提交；如已上架，准备紧急修复版本。
3. 在 Review Notes 中说明修复范围和隐私影响。

## 证据要求

1. 回滚前错误截图或日志摘要，不能包含宝宝内容、照片对象 key、token 或密钥。
2. 回滚后 API 验证结果。
3. 删除账号和照片对象能力仍可用的证明。
4. App Store Connect 状态截图。

## 当前状态

本方案为草案。正式发布前必须用真实生产域名和部署目录演练一次。
